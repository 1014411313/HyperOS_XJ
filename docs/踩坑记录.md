# 踩坑记录

> 这些坑已经踩过，后续不要重复。手机智能体改代码前先读一遍。

## 1. 最大的方向错误：把旧模块当底座

错误做法：

- 直接把 `source_snapshot/` 整个复制成新模块。
- 在旧 `thermal_core.sh`、`battery/scripts/*`、旧 WebUI、旧 `rearscreen.sh` 外面再套新 App/新引擎。

后果：

- 旧模块的执行文件、守护进程、权限逻辑、旧界面全部被带进来。
- 模块体积大、后台进程多、与旧脚本抢节点。
- 不是“新模块”，只是旧模块打补丁。

正确做法：

- 新模块底座是 `dist/HyperOS_XJ_New/`。
- 只保留新引擎、单 App、必要数据（温控场景、BAA/DTBO 载荷）。
- `source_snapshot/` 只做参考，不进新模块。

## 2. 第二个方向错误：把背屏拆成两个 App

错误做法：

- 主 App `com.hyperos.xj` + 独立背屏 App `com.hyperos.xj.rear`。

后果：

- 用户要装两个 APK。
- 引擎要同时管两个包。
- LSPosed 里出现两个模块，入口/scope/配置容易分裂。

正确做法：

- **单 App**：`com.hyperos.xj` 同时是 UI + LSPosed 背屏模块。
- 背屏 hook 代码在 `androidApp/src/main/java/com/hyperos/xj/rear/`。
- `assets/xposed_init` → `com.hyperos.xj.rear.RearHook`。
- manifest 的 `xposedscope` 只勾 `com.xiaomi.subscreencenter`。
- 模块里只有一个 APK：`app/HyperOS_XJ.apk`。

## 3. 背屏黑屏：不要禁用 SubScreenLauncher

错误做法：

```sh
pm disable com.xiaomi.subscreencenter
```

后果：

- 原生背屏时钟和宿主一起停掉。
- 卡片投不上时背屏直接黑。
- `pm disable` 跨重启持久，重启也恢复不了。

正确做法：

- hook `SubScreenLauncher.onResume`，把 `PanelView` 叠加到 `decorView`。
- `onPause` 移除。
- 原生时钟一直保留，最坏只是没有卡片。
- 旧版本留下的禁用状态在 `rear_boot_recover` / `rear off` 里 `pm enable` 清理。

## 4. standalone display 模式不要做默认

参考 APK 的 `StageActivity` / `RearLauncher` 用了：

- `am start --display`
- `am display move-stack`
- `dumpsys activity` 扫任务
- `cmd display power-on/reset`
- 多路径 `su`

这套能跑，但很脆：

- HyperOS 版本一改任务/显示行为就失效。
- 需要 root 命令，失败时容易黑屏。
- 还要处理 zombie task / refront / stage timeout。

新模块默认走 LSP overlay，不做 display 任务搬运。

## 5. Xposed stub 不能打进 APK

错误做法：

- 把 `de.robv.android.xposed.*` stub 放进 app 源码或 `implementation` 依赖。

后果：

- APK 内出现自己的 Xposed 类，与 LSPosed 提供的真实类冲突。
- `ClassCastException` / `LinkageError` / hook 不生效。

正确做法：

- `xposed-stubs` 独立 Gradle 模块。
- 主 App 用 `compileOnly(project(":xposed-stubs"))`。
- 校验 APK 时确认 `de/robv/android/xposed/*` 只有引用、没有类定义。

## 6. Kotlin 内置插件会把 stdlib 塞进小模块

现象：

- 一个很小的 Java LSP 模块 APK 变成 2.7MB，`classes.dex` 2.6MB。

原因：

- AGP 内置 Kotlin 自动带 `kotlin-stdlib`。

处理：

```kotlin
configurations.configureEach {
    exclude(group = "org.jetbrains.kotlin", module = "kotlin-stdlib")
}
packaging {
    resources.excludes += arrayOf("kotlin/**", ...)
}
```

## 7. `assets/xposed_init` 与 scope

必须同时有：

- `assets/xposed_init`：一行入口类名，例如 `com.hyperos.xj.rear.RearHook`
- manifest `<meta-data android:name="xposedmodule" ... />`
- `xposeddescription`
- `xposedminversion=82`
- `xposedscope` 指向 `res/values/arrays.xml` 的 `xposed_scope`

scope 只放 `com.xiaomi.subscreencenter`，不要放自己的包。

## 8. hook 进程读不到 App 的 SharedPreferences

原因：

- hook 在 `com.xiaomi.subscreencenter` 进程，App 的 SharedPreferences 在 `com.hyperos.xj` 进程。

处理：

- App 写外部配置：`/storage/emulated/0/Android/data/com.hyperos.xj/files/rear.conf`
- hook 读这份文件。
- 再写一份 `/data/local/tmp/xj_rear.conf` 兜底（root 可写，系统进程可读）。

不要用 `activity.getSharedPreferences("xjrear")` 去读，那会读到 subscreencenter 自己的配置。

## 9. 前台服务后台启动限制

现象：

- 广播/后台启动 `startForegroundService` 抛 `ForegroundServiceStartNotAllowedException`。

处理：

- `RearService.start()` 用 try/catch 包住。
- 服务起不来时不要影响 overlay；overlay 由 hook 进程自己跑。
- BootReceiver 的开机启动是豁免场景。

## 10. App 的 su 轮询不能阻塞主线程

错误：

- `readStatus()` 在 Main 线程直接 `ProcessBuilder("su", "-c", ...)`。

后果：

- 页面周期性冻结。

正确：

- `withContext(Dispatchers.IO)` 包住所有 `runAsRoot`。
- 轮询 2 秒左右；状态里的 sysinfo 做 60 秒缓存。

## 11. 状态 JSON 是平铺的

`xjctl status` 输出：

```json
{"key":"value","key2":"value2"}
```

没有嵌套对象，值全是字符串。App 用零依赖 `parseFlatJson`，不要引入 kotlinx.serialization。

## 12. settings.json 首次可能不存在

错误：

- `json_get` 发现文件不存在就直接返回空。

后果：

- 首次打开 App，温控页所有开关都是空/默认，但实际默认配置没落盘。

处理：

- `seed_settings()`：不存在就从 `default_settings.json` 复制。
- `json_get` / `json_set` 都先 ensure。

## 13. 单位不能猜错

Android 常见单位：

- `temp`: 0.1℃（375 = 37.5℃）
- `current_now`: µA（1800000 = 1.8A）
- `voltage_now`: µV（4480000 = 4.48V）
- `charge_full`: µAh（4680000 = 4680mAh）

双电芯 `voltage_now` 可能是串联总压：

- 先取 `voltage_avg` / `cell1_volt`
- 没有就 `voltage_now / 2`

## 14. 功率节点不能每拍重写

错误：

- 每 3 秒无条件写 `wired_chg_curr`。

后果：

- PMIC/PD 反复重协商，功率 0W↔50W 方波。

处理：

- 节点已符合签名就跳过。
- 同档位但节点被驱动复位时，按 `cg_min_write_gap`（默认 60s）节流。
- 旁路时不要先写功率档再写旁路电流；`run_tick` 已经调整顺序。

## 15. 旁路与功率档会互相覆盖

旧顺序：

1. `power_apply`
2. 判旁路
3. `apply_bypass` 写 charge 节点

问题：

- 每拍先写档位、再写旁路，节点来回覆盖。

处理：

- 旁路判定在前；旁路时直接 `apply_bypass` 并 return。
- 离开旁路时 `release_charge` 再 `power_apply`。

## 16. BAA 必须在 PID1 namespace 挂载

原因：

- `batteryantiaging` 只看 PID1 mount namespace。
- 在当前 shell namespace `mount --bind`，系统服务看不到。

处理：

- `xjctl.sh` 对 `battery` 命令用 `nsenter -t 1 -m` re-exec。
- 没有 nsenter 时记录 `XJ_NO_NSENTER=1`，尽力而为。

## 17. BAA 载荷不能乱回退

错误：

- 找不到本机型 payload 就回退 xuanyuan。

后果：

- 给错误机型挂错误充电配置，风险高。

正确：

- `baa_src()` 只认 `payload_BAA_config_<dev>.json`。
- 不支持机型就 mount 失败，不要乱挂。

## 18. PSS 禁用会隐藏电池健康度

`PowerSaveService` 被禁用后：

- `com.miui.securitycenter.remote` 不启动。
- `BatteryHealthUtils` 不运行。
- 设置里的电池健康度可能不显示。

所以：

- 只有 `pss_disable=1` 才禁用。
- `battery unlock off` 必须恢复 PSS。
- 记录 `pss_disabled_by_module`，只恢复模块自己禁的。

## 19. DTBO 刷入是高危操作

- `dd` 写 `dtbo_a/b` 分区，错误镜像/错误槽位可能变砖。
- 新模块只提供镜像，不自动刷。
- App 的 DTBO 按钮目前是占位。
- 真要做：先备份当前槽位、校验镜像 magic/size、二次确认、重启生效。

## 20. 模块 zip 权限

- `META-INF/com/google/android/update-binary` 必须 0755。
- `.sh` 必须 0755（至少 `service.sh`/`customize.sh`/`uninstall.sh`/`engine/*.sh`）。
- lib 脚本 0644 即可（被 source）。
- APK/JSON/IMG 0644。

Windows 没有 `zip`/`7z`/Python 时，用 .NET `ZipFile` + `ExternalAttributes` 写 Unix mode；`ExternalAttributes` 是 Int32，0755 要写负数 `-2115174400`。

## 21. 构建环境

- 本机 `GRADLE_USER_HOME=D:\gradle`。
- 离线构建加 `--offline`。
- Android SDK 在 `D:\Android\Sdk`，可用 `aapt.exe` / `dexdump.exe` 验证 APK。
- 不要假设有 `zip`、`7z`、`python`、`jadx`。
